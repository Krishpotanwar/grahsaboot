# R3 Frontend: god's-eye shell, engine, basemaps, UI stack, fused design system

Date: 2026-10-05 (all "accessed" dates are 2026-10-05). Author: Sonnet research worker. Domain: map/globe engine, basemaps, UI stack, design system.
Updated for the coordinator's owner-decision message: FULL 3D CITY GLOBE (Fast & Furious "God's Eye" look), live satellite positions, next-pass, NVG/FLIR/CRT modes, perf budget with low-end fallback. Person tracking and CCTV are out of scope and not researched.

Fact vs inference: every row in section 1 and 2 is a fact from a primary page or the npm registry unless marked (inference) or UNVERIFIED. npm versions/dates come straight from `https://registry.npmjs.org/<pkg>` (queried 2026-10-05). Several vendor pages were summarised by a fetch tool; where two summaries disagreed I re-read the raw HTML (noted).

---

## 0. Decision in six lines

1. Engine: **MapLibre GL JS 6.12.0 (BSD-3-Clause)** for everything: landing globe, tilted 3D city, evidence context map. One engine, one licence, no vendor key needed for the core. Cesium is the strongest rival (section 6 argues for it) but its free ion tier is not licensed for a commercial product and the Google photorealistic city has cost, ToS and dated-evidence problems.
2. The 3D city is **stylised, not photoreal**: extruded OSM/OpenMapTiles buildings + free terrain on the globe, dark HUD styling. It fits the brutalist/telemetry design, costs ₹0, and avoids implying a photo date.
3. Evidence comparison (swipe, side-by-side, section x date matrix) is **plain DOM, not map-engine work**: two pixel-aligned PNGs (same bbox/size from one Process API request pair) with `clip-path` + native `<input type="range">`. Prints, works on weak phones, passes WCAG 2.5.7.
4. Basemaps: dark vector = **OpenFreeMap** at launch (commercial OK, no key, no SLA), **Protomaps PMTiles on Cloudflare R2** as the owned fallback; globe skin = **NASA GIBS / Blue Marble**; satellite context = **EOX 2016 (CC BY 4.0) only**. EOX 2018-2025 are CC BY-NC-SA: not usable for a commercial product. MapTiler and Stadia free tiers are non-commercial. Esri World Imagery: terms UNVERIFIED, defer.
5. Live satellites: CelesTrak GP JSON fetched **server-side every 2 h** into a static file, `satellite.js 7.1.0` (MIT) in a Web Worker. "Next pass" must be filtered to **daytime descending passes** (my SGP4 test returned night-time ascending passes that never produce imagery) and ideally replaced by ESA's published **Sentinel-2 acquisition-plan KML**.
6. Design system: brutalist structure + minimalist restraint + Apple motion, with explicit conflict rules and **three contrast corrections to the source skills** (section 5.2).

## 4. The god's-eye shell: what to build and how it degrades

### 4.1 Camera and look (all MapLibre)
- Dark globe (`setProjection({type:'globe'})`), sky/atmosphere on, GIBS skin below zoom ~5, OpenFreeMap dark above.
- Landing: slow rotation (about 1 revolution per 3 min, stops after 30 s idle or on interaction, off under reduced motion or battery saver).
- Fly-to-site: `flyTo` with pitch 55-65 degrees and a bearing orbit after landing (`easeTo` loop, interruptible), duration 3-5 s; reduced motion = `jumpTo` + 200 ms cross-fade.
- 3D city appears at zoom >= 14: terrain + extruded buildings with a single flat dark fill and one hairline-edge colour (no gradients). Label "Heights approximate".
- HUD: corner brackets, coordinate readout, scale, compass; mono caps micro-labels.

### 4.2 Live satellites (owner request)
- Data path: cron (every 2 h, matches CelesTrak's update cadence) fetches JSON for Sentinel-2A/2B/2C, Sentinel-1A/1C/1D, Landsat 8/9 -> static `sats.json` (a few KB). Browser reads that file only. This respects the 403 "one download per update" policy and the 250 MB/day/IP cap.
- Worker with `satellite.js`: every second compute sub-satellite point; draw a marker, last/next 45 min ground track, and a swath footprint polygon (Sentinel-2 half-width 145 km; use per-mission values: S1 and Landsat differ). Altitude is not drawn (786 km is invisible at globe scale and 3D orbit lines need a custom three.js layer; cosmetic, skip). 
- "Next imaging over your site": 1) server cron parses ESA Sentinel-2 KML plans and intersects them with the saved polygon -> dates with "planned" label; 2) fallback SGP4 scan 10 days at 60 s steps, keep only sun-lit descending passes (local time about 10:30 for S2), mark "estimated". Always show: "A pass is not a usable image; clouds can block it. Radar (Sentinel-1) sees through cloud."
- Honest status text: "S2A: extended operations. S2C: primary." (SentiWiki).
- The only green on screen (`--live` #4AF626) is the "LIVE" dot next to this readout (brutalist rule: green for one element only).

### 4.3 Sensor look modes (NVG / FLIR / CRT)
- Name them for people: **Standard, Night, Heat, Retro**, under a small "Look" menu, default Standard, labelled "Style only. Not real night or thermal data."
- MapLibre has no post-process stage. Implement with CSS on the map canvas wrapper: Night = `grayscale(1) sepia(1) hue-rotate(70deg) saturate(4) brightness(1.2) contrast(1.4)`; Heat = `grayscale(1) contrast(1.6)` plus a 3-step colour overlay; Retro = scanline `repeating-linear-gradient` overlay (the only gradient allowed in the product, user-opt-in, brutalist skill sanctions it for CRT) + subtle vignette. (inference) A CSS filter on a full-screen WebGL canvas adds a compositor pass; expect a visible FPS cost on weak GPUs, so these modes are Tier 3 only.
- Never applied to: the evidence viewer, the matrix, the report, print. Evidence integrity beats style.
- Cesium would do this properly in GLSL (`PostProcessStage`, built-in `createNightVisionStage`), the best argument for the phase-2 module.

### 4.4 Performance tiers and fallback (targets to verify, not measurements)
| Tier | Condition (checked in this order) | What runs |
|---|---|---|
| T0 Static | no WebGL2, or `failIfMajorPerformanceCaveat` trips, or `saveData` | No map. Coordinate form + site summary + flat DOM evidence viewer + matrix. Everything needed for the product still works |
| T1 Flat | WebGL2 ok but `deviceMemory` <= 2, or FPS probe < 24 | MapLibre Mercator, no pitch/terrain/buildings, `pixelRatio` capped at 1, no satellites animation (static list) |
| T2 Globe | default | Globe + flyTo, satellites ticking at 1 Hz, no shader modes, no extrusion above city zoom |
| T3 City | `deviceMemory` >= 4 and cores >= 6 (where exposed) and FPS probe >= 45 | Terrain + extrusion + shader modes + orbit |

- Signals: `navigator.deviceMemory` (Chromium only, coarse), `hardwareConcurrency`, WebGL2 availability, `prefers-reduced-motion`, `Save-Data`/`connection.saveData` (Chromium only), plus a 1.5 s `requestAnimationFrame` probe after first render that downgrades one tier, never upgrades silently. Safari/Firefox lack some signals: start at T2, rely on the probe.
- Budgets to test on a real ₹10-12k Android over throttled 4G (Lighthouse + DevTools 4x CPU): initial route JS <= 150 KB gz before the map chunk; map chunk lazy-loaded behind the landing hero; first meaningful paint <= 3 s; interaction <= 100 ms; map at >= 30 fps median in T2; memory under 350 MB. These are targets I propose, not figures found in any source.
- User-visible: a quiet "Lite mode" chip in the HUD with "Switch to full" so downgrades are reversible (Apple: agency).

## 5. Fused design system

### 5.1 How the three skills combine without fighting

Role split (each skill owns a layer; where two rules clash, the layer owner wins):

| Layer | Owner | What it controls |
|---|---|---|
| Structure and data surfaces | industrial-brutalist-ui (Tactical Telemetry mode for Ops, Swiss Print mode for the light/report theme) | grids, hairlines, square corners, mono caps micro-labels, ASCII brackets `[ ]`, crosshair ticks, `<data>/<samp>/<kbd>/<output>/<dl>` semantics, red as the single accent |
| Content, rhythm, tone | minimalist-ui | warm neutrals, whitespace on landing/new-investigation/report, editorial serif for page titles, plain copy, pastel meaning tints, no shadows or gradients |
| Motion, touch, materials, principles | apple-design | springs, interruptible and 1:1 drag, velocity handoff, translucent HUD over the map, sheets, rubber-banding, reduced-motion/transparency/contrast, eight principles (agency, familiarity, simplicity-not-minimalism) |

Explicit conflict rules:

| Conflict | Resolution |
|---|---|
| Brutalist: pick ONE substrate, never mix light and dark. Owner wants dark ops + light. | Two themes, one active at a time, switched globally (default follows `prefers-color-scheme`, user toggle). Dark = Tactical Telemetry. Light = Swiss Print palette tuned with minimalist warm neutrals. Report/print is its own light document. Never half-and-half in one view. |
| Brutalist: no `border-radius`. Minimalist: 4-12px. Apple: rounded touch targets. | Radius 0 on every structural thing: panels, cells, inputs, buttons, chips, map frame. Only affordance glyphs are round: sheet grabber, slider thumb, radio/switch thumb, live dot. |
| Brutalist: no translucency. Apple: materials. | Only HUD panels floating over the map may be translucent: background alpha **0.92**, `backdrop-filter: blur(12px)` in T2/T3 only, 1px border, never stacked, never over text. Alpha 0.92 keeps `--fg-3` text at 4.72:1 even over a pure-white map (0.86 gave 3.89:1: fail). Under `prefers-reduced-transparency` or T0/T1: solid. |
| Brutalist: ALL-CAPS everything. Minimalist: sentence-case warm copy. First-timers need plain language. | Caps + tracking only for micro-labels, units, IDs, status (mono, 12px). Headings, buttons, body, errors, help text are sentence case in Geist. |
| Brutalist: 10-14 px mono. | Floor 12px. Smaller is not legible on low-end Android in sunlight. |
| Minimalist: no gradients. Brutalist: scanlines allowed for CRT. | No gradients anywhere except the opt-in "Retro" look overlay. |
| Minimalist: no shadows >0.05. Brutalist: none. | None. Separation = 1px hairlines + scrim over modals. |
| Minimalist: no Inter/Roboto. Brutalist lists Inter. Apple: system font. | Geist (variable) for UI. Rationale: Android system font is Roboto (banned) and iOS has SF, so only a bundled face guarantees identical metrics; Geist has no Devanagari so `Noto Sans Devanagari` (unicode-range, loaded only for Hindi text) fills in. |
| Brutalist: red is the ONLY accent. Red also reads "error" to non-experts. | Red = target lock marks (corner ticks), rejected/error, destructive. Primary button is NOT red. Observation validity is shape-coded (see 5.4), not colour-coded. |
| Brutalist: green optional for one element. | `#4AF626` exclusively on the LIVE satellite dot/readout. |
| Apple: simplicity is not minimalism. | Where brutalist density would overwhelm a first-timer, add a plain-language line or a "What is this?" popover, not more ornament. |
| Apple: slow loops near 0.2 Hz to avoid. Brutalist/minimalist ambient motion. | No ambient motion except the globe drift (about 0.0055 Hz, auto-stops, off for reduced motion). |

### 5.4 Layout, spacing, shape
- Spacing scale (4px base): 4, 8, 12, 16, 24, 32, 48, 64, 96. Landing/report use 64-96 vertical rhythm (minimalist); workbench uses 8-16 (brutalist density).
- Grid: 12 columns, 1px gutters drawn by `display:grid; gap:1px; background: var(--line)` with children `background: var(--surface)` (brutalist directive 8.1). Content width max 1200px for text pages, full-bleed for map.
- Touch targets: 44x44 px minimum (Apple), never below WCAG 2.5.8's 24px.
- Corners: 0 (see conflict table). Borders: 1px structure, 2px for selected/target.
- Observation validity glyphs (monochrome, with label): solid square "VALID", half-filled "PARTIAL", hollow square "NO DATA", cross in red "REJECTED (cloud/quality)". In light theme the pastel chip may repeat the same word as a secondary cue.
- Site boundary: 2px `--fg` line with red corner ticks (the "target lock" gesture) and dimensions label in mono.

### 5.5 Motion (Motion 14 / 13.5, springs map to Apple damping + response)

| Interaction | Spring (`motion`) | Notes |
|---|---|---|
| Default UI move/reposition | `{type:'spring', duration:0.4, bounce:0}` (damping 1.0, response 0.4) | critically damped |
| Sheet / drawer | `{type:'spring', duration:0.3, bounce:0.2}` (about damping 0.8) | bounce only because a drag preceded it; enter and exit along the same edge |
| Swipe divider release | spring with release velocity handed in; project landing with `v/1000 * d/(1-d)`, d = 0.998; snap to nearest of 0 / 50 / 100 % | 1:1 tracking with `setPointerCapture`; 10px hysteresis before committing direction |
| Press feedback | `scale(0.97)` on pointerdown, 100 ms | respond on press, not release |
| Landing/report scroll entry | `translateY(12px)` + opacity, 600 ms `cubic-bezier(0.16,1,0.3,1)`, `IntersectionObserver`, stagger 80 ms | landing and report only; the workbench has no decorative motion |
| Globe fly-to | MapLibre `flyTo` curve 1.4, 3-5 s, interruptible | reduced motion: `jumpTo` + 200 ms cross-fade |

Rules: animate only `transform`/`opacity`; interruptible always (start from live value); `prefers-reduced-motion` => cross-fades only, no bounce, no auto-rotate; `prefers-reduced-transparency` => solid panels; `prefers-contrast: more` => `--control` borders at full `--fg`.

### 5.6 Component rules
- Buttons: primary solid inverted (`--primary-bg`), 0 radius, 44px high, label sentence case. Secondary = 1px `--control` outline. Destructive = outline in `--accent-fg` with a confirm step only for irreversible actions (Apple: use confirmations sparingly; offer Undo elsewhere).
- Inputs: 1px `--control`, label above (never placeholder-only), inline validation on blur, native `<input type=date>`.
- Chips/tags: square, mono caps 12px, 1px outline; light theme may add pastel fill.
- Panels: 1px `--line`, header strip with `[ TITLE ]` bracket micro-label and one action.
- Tables/matrix: cells are buttons, 44px min height on touch, `role="grid"`, roving tabindex, arrow-key movement; row header = section name + chainage, column header = actual acquisition date (not the requested bin).
- Dialogs/sheets: Base UI Dialog; mobile uses bottom sheet with grabber; focus trapped; Esc closes.
- Toasts: for completion/status only (Apple four feedback kinds: status, completion, warning, error).
- Icons: Phosphor Bold, 20px, 2px-equivalent stroke weight constant, always paired with a text label in primary flows.
- `<kbd>` for keyboard hints on desktop only (minimalist-ui style, square).
- Empty/loading/partial/failure/expired/quota-blocked states are designed screens, not spinners (PRD l.98).

## 8. Strongest argument against this pick (steelman for Cesium + Google)

The owner asked for a Fast & Furious God's Eye. The reference product (Bilawal Sidhu's God's Eye View) looks like that precisely because of CesiumJS + Google Photorealistic 3D Tiles + real GLSL post-processing. A MapLibre extruded-polygon city on India's sparse OSM heights will look like a flat dark map with grey boxes, and CSS filters are a cheap imitation of FLIR/NVG. Cesium gives true orbit rendering with altitude, `SampledPositionProperty` satellites, native split-screen compare, and custom shaders; it is the established tool for exactly this shell. Google's tiles at $6 per 1,000 sessions beyond the free 1,000 are not crippling, and the product will likely not hit 100,000 sessions soon. If the "wow" factor is what wins the first users and investors, MapLibre may under-deliver the thing the owner explicitly chose.

Why I still pick MapLibre for launch: (1) the product's value is trustworthy dated evidence, and Google tiles have unknown mixed capture dates and a ToS clause ("No Use With Non-Google Maps ... with or near a non-Google Map") that may prohibit putting our evidence imagery near them; (2) Cesium ion's free tier is for personal/non-commercial use, and the reference app avoids this only because each user brings their own keys; (3) low-end Indian Android phones are the audience, and Cesium plus photoreal tiles is the heaviest option (the Cesium forum itself warns of crashes on low-RAM devices); (4) free 3D buildings and terrain for Cesium need an offline build pipeline that does not fit one month and ₹0; (5) a second engine breaks the "minimal components" rule.

Mitigation, if the owner insists on the cinematic look: add a **lazy-loaded "Cinematic" module** (CesiumJS 1.146, Node >=22 build, Apache-2.0) behind a feature flag, desktop-class devices only, using Google tiles through a server-side key proxy, with (a) written Google confirmation on overlaying non-Google evidence or a hard rule that evidence is never shown inside that view, (b) a monthly budget cap, (c) the attribution line and no caching. Estimated cost at 10,000 sessions/month: (9,000/1000) x $6.00 = $54 list price (India price list not read). Treat it as a marketing/demo view, not the workbench.

### Q1. NVG / FLIR / CRT in MapLibre 6.12: four techniques, cheapest first

MapLibre has no post-process stage. A `CustomLayerInterface` (`render(gl,args)`, `renderingMode '2d'|'3d'`) draws into the scene; the official three.js example reuses the map's canvas/context and sets `autoClear=false` [example](https://maplibre.org/maplibre-gl-js/docs/examples/add-a-3d-model-to-globe-using-threejs/). It is for adding geometry, not for reading back the finished frame, so it is the wrong tool for a screen-space look.

| # | Technique | Frame cost (inference, not measured) | Use for |
|---|---|---|---|
| A | **Style swap**: change paint properties on layers that already render. Raster layers have `raster-hue-rotate`, `raster-saturation`, `raster-contrast`, `raster-brightness-min/max` (confirmed in `@maplibre/maplibre-gl-style-spec` 26.4.4). Vector colours via `setPaintProperty`. | About zero: same shaders, same draw calls | Night (green phosphor on black), Heat (greyscale ramp), the default for T2 |
| B | **DOM overlay**: absolutely positioned div with `pointer-events:none` (scanlines, vignette, grain via a tiny static PNG) | Small: one extra composited layer, no WebGL work | Retro/CRT scanlines, HUD vignette |
| C | **CSS `filter` on the map container** | Medium to high on weak GPUs: the browser must render the WebGL canvas to an offscreen surface and filter it each frame | T3 only, desktop-class |
| D | **Second WebGL canvas** that samples `map.getCanvas()` as a texture and applies a real fragment shader | Highest: a full-frame texture copy + a full-screen pass every frame, plus a second GL context (memory) | Optional "cinematic" T3 on desktop; skip on mobile |

Minimal code, A (free): 
```ts

  standard: { hue: 0,   sat: 0,  con: 0,   bmin: 0,    bmax: 1 },

};
function setLook(map: maplibregl.Map, k: keyof typeof LOOKS) {

      'raster-contrast': l.con, 'raster-brightness-min': l.bmin, 'raster-brightness-max': l.bmax })
      .forEach(([p, v]) => map.setPaintProperty(id, p, v));
  map.setPaintProperty('building-3d', 'fill-extrusion-color', k === 'night' ? '#1c3a1c' : '#2a2a2a');

```


D (heavy; real shader). Valid only if the texture upload runs synchronously inside the map's `render` event; otherwise `canvasContextAttributes.preserveDrawingBuffer` must be true (default false per MapOptions) and costs more:
```ts
const fx = document.createElement('canvas'); fx.className = 'fx-overlay';          // sits over the map, pointer-events:none

/* compile once: vertex = fullscreen triangle; fragment (night):
   vec3 c = texture(u_scene, v_uv).rgb; float y = dot(c, vec3(.299,.587,.114));

map.on('render', () => {
```

### Q2. Steelman CesiumJS without ion, then decide

Facts: CesiumJS 1.146.0 Apache-2.0; its `Cesium.js` build file is **6,080,574 bytes minified, 1,773,937 bytes gzip -9** (measured from jsDelivr), plus Workers/Assets/Widgets loaded separately (Widgets CSS 30.7 KB). MapLibre 6.12.0: `maplibre-gl.mjs` 597,295 B (152 KB gz) + `maplibre-gl-shared.mjs` 516,951 B (147 KB gz) + worker 19 KB + CSS 83 KB: about 300 KB gz of JS. Cesium is therefore about 6x heavier on the wire (my measurement of the main bundle only; real totals not measured).

What a ₹0, commercial-OK Cesium would need, and what is verified:
- **Terrain**: `CesiumTerrainProvider.fromUrl(yourUrl)` works without an ion token and reads quantized-mesh or heightmap [ref](https://cesium.com/learn/cesiumjs/ref-doc/CesiumTerrainProvider.html). But no free commercial quantized-mesh service exists that I could verify: ion's Cesium World Terrain is Community = non-commercial; MapTiler's free quantized-mesh tiles sit on a Free plan limited to "personal or non-commercial use" (pricing page, section 1 B3; terrain-specific terms not read). That leaves **self-building** from Copernicus DEM GLO-30 (free; some tiles not released; India tile status not checked) with open tools such as Cesium Terrain Builder (named in search results, not evaluated) and hosting on R2. A pipeline, not a switch. AWS Terrarium PNG tiles (free) are not a Cesium-native format; a custom `TerrainProvider` returning `HeightmapTerrainData` is the extension point (I did not verify an existing maintained package: UNVERIFIED).
- **Buildings**: Cesium has no native Mapbox-vector-tile consumer. Options: Overture/OSM GeoJSON -> extruded polygon entities (main-thread geometry batching; fine for hundreds to low thousands, risky for city-scale on a phone: inference), or convert to 3D Tiles offline (tool not evaluated). Overture footprint quality caveat in India applies equally.
- **Shaders**: `PostProcessStage` (custom GLSL, `textureScale` to cut cost, built-in `createNightVisionStage`, `createBlackAndWhiteStage`, `createEdgeDetectionStage`) is the real advantage over Q1's techniques [ref](https://cesium.com/learn/cesiumjs/ref-doc/PostProcessStage.html).
- **Other real wins**: true altitude orbits (`SampledPositionProperty`), native `splitDirection`, depth-correct 3D lines.
- **Low-end Android**: the Cesium forum's own guidance is to raise `maximumScreenSpaceError` (e.g. 64), cap `maximumMemoryUsage` (e.g. 128), use `requestRenderMode`, and "not all Android devices will work". No measured FPS on a ₹10-12k phone exists for either engine.

Does it look better than MapLibre at ₹0? **No.** Free terrain + free buildings + dark imagery is the same content in both. The visual leap in the reference is Google photoreal tiles; that is E3/E4 in the ledger (paid, no caching, no analysis, overlay clause). The remaining Cesium edge is shader polish and altitude-correct orbits, which MapLibre can approximate: the custom-layer path with three.js already exists for the globe (official example above) if altitude trails are wanted later.

MapLibre "film" recipe at ₹0 (all sources verified reachable today with CORS `*`): globe + sky/atmosphere; **NASA Black Marble night skin** (`VIIRS_Black_Marble` 2016-01-01, GIBS tile returned 200 PNG, 88 KB) under zoom ~5; Blue Marble shaded relief (200 JPEG, 18 KB) as day skin; AWS terrarium DEM (200 PNG, 46 KB) as `raster-dem`; OpenFreeMap buildings extruded dark; pitch 60, bearing orbit; Look modes A+B.

**Decision: MapLibre. Revisit Cesium only if (1) the owner pays for ion Commercial ($149/month) or gets written Google clearance, and (2) real-device tests show MapLibre looks inadequate.** If revisited, build it as the lazy "Cinematic" module described in section 8.

### Q3. Rendering a COG window: decode, reproject, align, swipe

Measured against a live Sentinel-2 L2A scene (Earth Search STAC today: `S2B_44QKJ_20261002_0_L2A`, tile 44QKJ over Nagpur, CRS **EPSG:32644 (UTM)**):
- `TCI.tif` is on `sentinel-cogs.s3.us-west-2.amazonaws.com`, 250,546,181 bytes, 10980 x 10980 px, **5 images (overviews)**, **1024 x 1024 internal tiles**, `Access-Control-Allow-Origin: *`, `Accept-Ranges: bytes`, and a `Range` request returns `206`. So browser reads work with no proxy. `SCL.tif` and `B04.tif` are siblings.
- geotiff.js **3.0.5, MIT**, published 2026-03-11, deps include lerc, pako, zstddec, web-worker (npm). `fromUrl()` open took **5.7 s** from this VM (headers + IFDs for 5 levels); a 300 x 300 px (3 x 3 km) `readRasters({window, samples:[0,1,2], interleave:true})` took **2.5 s** first call and **3.8 s** for a 290 x 288 px window (network-bound; a phone on 4G will differ).
- **Bandwidth arithmetic (inference from the measured file size)**: 250.5 MB / (11 x 11 = 121 tiles x about 1.33 for overviews) is about **1.5 MB per full-resolution 1024-px tile**. A 3 km site usually touches 1 tile and up to 4 when it sits on a tile corner: **about 1.5-6 MB per date**; a before/after pair 3-12 MB; a 12-window timeline about 18-72 MB; a 20 km road corridor several times that. That is heavy for metered Indian mobile data. PNG renders from the Process API are about tens to low hundreds of KB (not measured here).

`@geomatico/maplibre-cog-protocol` 0.10.0 (MIT, published 2026-09-18, MapLibre ^4.5 / ^5 / ^6) registers a `cog://` protocol, **but requires COGs already in EPSG:3857 and "does not reproject; reading a COG in any other projection throws an error"** [README](https://github.com/geomatico/maplibre-cog-protocol). Sentinel-2 COGs are UTM, so it **cannot** serve them. Globe support is not documented there. `titiler`-style free hosting needs a server (excluded by "no PNG pipeline" and ₹0). `@developmentseed/deck.gl-geotiff` 0.8.1 reprojects but pulls deck.gl (rejected in E6).

Therefore: **own the decode+reproject, 60 lines, in a Worker**. Tested core (Node, bilinear, UTM 44N -> EPSG:3857 shared output grid; proj4 2.22.0 MIT):
```ts
// worker.ts (geotiff 3.0.5, proj4 2.22.0)
import { fromUrl } from 'geotiff'; import proj4 from 'proj4';
proj4.defs('EPSG:32644', '+proj=utm +zone=44 +datum=WGS84 +units=m +no_defs'); // derive from STAC proj:code per scene
export async function renderWindow(url: string, utm: string, out: [number,number,number,number], N = 512) {
  const tiff = await fromUrl(url), img = await tiff.getImage();                 // pick overview via tiff.getImage(i) for low data
  const [x0,, , y1] = img.getBoundingBox(), res = (img.getBoundingBox()[2] - x0) / img.getWidth();
  const toM = proj4(utm, 'EPSG:3857'), fromM = proj4('EPSG:3857', utm);
  const cs = [[out[0],out[1]],[out[2],out[1]],[out[2],out[3]],[out[0],out[3]]].map(p => fromM.forward(p));
  const sx0 = Math.min(...cs.map(p=>p[0])) - 2*res, sx1 = Math.max(...cs.map(p=>p[0])) + 2*res;
  const sy0 = Math.min(...cs.map(p=>p[1])) - 2*res, sy1 = Math.max(...cs.map(p=>p[1])) + 2*res;
  const win = [Math.floor((sx0-x0)/res), Math.floor((y1-sy1)/res), Math.ceil((sx1-x0)/res), Math.ceil((y1-sy0)/res)];
  const W = win[2]-win[0], H = win[3]-win[1];
  const src = await tiff.readRasters({ window: win, samples: [0,1,2], interleave: true }) as Uint8Array;
  const px = new Uint8ClampedArray(N*N*4);
  for (let j=0;j<N;j++) for (let i=0;i<N;i++) {                                  // inverse map each OUTPUT pixel
    const [ux,uy] = fromM.forward([out[0]+(i+.5)/N*(out[2]-out[0]), out[3]-(j+.5)/N*(out[3]-out[1])]);
    const fx=(ux-x0)/res-win[0]-.5, fy=(y1-uy)/res-win[1]-.5, ix=Math.floor(fx), iy=Math.floor(fy), ax=fx-ix, ay=fy-iy, o=(j*N+i)*4;
    if (ix<0||iy<0||ix+1>=W||iy+1>=H) continue;                                  // alpha 0 = outside this scene
    for (let b=0;b<3;b++){const g=(x:number,y:number)=>src[(y*W+x)*3+b];
      px[o+b]=g(ix,iy)*(1-ax)*(1-ay)+g(ix+1,iy)*ax*(1-ay)+g(ix,iy+1)*(1-ax)*ay+g(ix+1,iy+1)*ax*ay;} px[o+3]=255;
  }
  return new ImageData(px, N, N);                                                // transfer the buffer back
}
```
Measured: bilinear reprojection of a 256 x 256 output took **32 ms** (Node, one thread, 290 x 288 source window); N=512 would be about 4x that (inference). Use **nearest** for SCL (class codes must not be blended) and a separate call for it. Evidence integrity: bilinear softening of a 10 m pixel is a display resampling; record "bilinear resample to a common 3857 grid" in provenance, or use nearest for the evidence frame and bilinear only for pretty zoomed views.

**Pixel alignment for the swipe**: compute ONE output bbox (EPSG:3857, from the confirmed polygon + padding) and the same N for both dates. Both `ImageData`s are then the same size and same geographic grid even when the scenes are different tiles, different relative orbits or different UTM zones (the function reprojects each from its own CRS). Draw each into a `<canvas>`, stack them in the DOM, clip the top one with `clip-path`, drive with the range input. No map is involved in the comparison, so there is no engine reprojection error. For the context map, `map.addSource('before',{type:'image',url:canvas.toDataURL(),coordinates:[TL,TR,BR,BL]})` with `raster-fade-duration:0`; the corners are the 3857 bbox converted to lon/lat (the tested example gave TL 78.62547,21.20345 and BR 78.65242,21.17832). MapLibre has no per-layer clip, so on-map comparison is opacity-crossfade only; keep the clip-swipe in the DOM. Do not mix a fetched, reprojected evidence image with the style filters in Q1.

**Honest recommendation on "no PNG pipeline"**
1. For a site <= about 5 km on desktop/Wi-Fi: browser COG is good: no render-server cost, no Process-API units spent, and the user can zoom into 10 m pixels.
2. For mobile data: gate by `saveData`/`effectiveType`; read an overview level (each level quarters the bytes) first, then refine on demand; cache decoded windows in IndexedDB; fetch before/after first, timeline lazily.
3. **Provenance risk the imagery agent must answer**: pixels decoded in the user's browser cannot be attested by the server. The architecture's retained-evidence rule ("copy accepted output bytes into private storage", ARCHITECTURE_V2.md l.111) implies a server-held copy. If the report is to be defensible, either the server re-renders the same window (a PNG pipeline after all) or the report states the evidence is reproduced from public scene IDs and is user-generated. This is a design decision, not a library choice.
4. Rejection of cloudy dates needs SCL before showing TCI (SCL is 20 m, smaller): fetch SCL first, compute valid fraction in the Worker, then decide whether to pull TCI at all. That actually saves bandwidth.

### Q4. Live satellite layer, minimal code in MapLibre

Data: static `sats.json` from the 2-hour cron (CelesTrak `FORMAT=json`; today's resource group has S2A 40697, S2B 42063, S2C 60989, S1A 39634, Landsat 9 49260, Landsat 8; S1C/S1D found by `NAME=`). Tested (Node): 181 track points (+/-45 min at 30 s) and a 363-point swath polygon take **1.7-5.5 ms per satellite**. // worker: build GeoJSON once per second for markers, every 30 s for trails/swaths
```ts
const dest=([lo,la]:number[],b:number,d:number)=>{const a=d/6371.0088,p=la*rad,t=b*rad,
  la2=Math.asin(Math.sin(p)*Math.cos(a)+Math.cos(p)*Math.sin(a)*Math.cos(t));
  return [(lo*rad+Math.atan2(Math.sin(t)*Math.sin(a)*Math.cos(p),Math.cos(a)-Math.sin(p)*Math.sin(la2)))*deg, la2*deg]};
function trackAndSwath(rec, half, now, mins=45, step=30){

    pts.push([degreesLong(g.longitude),degreesLat(g.latitude)]);}
  const tr=unwrapLon(pts), L=[],R=[];                       // unwrap so lines cross the antimeridian continuously
  tr.forEach((p,i)=>{const b=bearing(tr[Math.max(0,i-1)],tr[Math.min(tr.length-1,i+1)]);L.push(dest(p,b-90,half));R.push(dest(p,b+90,half));});
  return { track: tr, swath: [...L,...R.reverse(),L[0]] };
}
// main thread
map.addSource('sat-live',{type:'geojson',data:EMPTY});   // points (now)
map.addSource('sat-trail',{type:'geojson',data:EMPTY});  // lines (past solid, future dashed via two features)
map.addSource('sat-swath',{type:'geojson',data:EMPTY});  // polygons
map.addLayer({id:'swath',type:'fill',source:'sat-swath',paint:{'fill-color':'#EAEAEA','fill-opacity':0.08}});
map.addLayer({id:'trail',type:'line',source:'sat-trail',paint:{'line-color':'#EAEAEA','line-width':1,'line-dasharray':[2,2]}});
map.addLayer({id:'sat',type:'circle',source:'sat-live',paint:{'circle-radius':4,'circle-color':'#4AF626','circle-stroke-color':'#0A0A0A','circle-stroke-width':1}});
setInterval(()=>worker.postMessage({t:Date.now()}), 1000); worker.onmessage=e=>map.getSource('sat-live').setData(e.data.points);
```
This draws at the surface (no altitude) in about 3 layers and updates only a few-feature GeoJSON per second, cheap on any tier. Labels use a `symbol` layer with `text-field` (needs a glyph source; OpenFreeMap style supplies fonts). Altitude-correct 3D orbit rings would need the three.js custom layer: skip for launch. ### Q5. Lite-mode triggers, ranked by device (decide at load, then one-way downgrade)

Order = reliability of the signal and severity of the response. Implement as one `chooseTier()` plus a `webglcontextlost` handler.

| Rank | Trigger | How to detect | Where it works | Response |
|---|---|---|---|---|
| 1 | WebGL2 absent or context creation fails (hard fail; MapLibre 6 removed WebGL1; WebGL2 is 96.44% of browsers per caniuse, so the 3.5% matters at India scale) | `canvas.getContext('webgl2')` null; try/catch around `new Map()` | all browsers | **T0 static** (form + DOM evidence viewer + matrix) |
| 2 | Software or major-performance-caveat renderer (SwiftShader, blocklisted GPU) | `new Map({failIfMajorPerformanceCaveat:true})` throws; `WEBGL_debug_renderer_info` string contains `SwiftShader`/`llvmpipe` | Chromium/Firefox | T0 (or T1 if the user clicks "try anyway") |
| 3 | Context lost mid-session | `canvas.addEventListener('webglcontextlost')` | all | drop one tier, show chip "Lite mode" |
| 4 | Data saver / slow network | `navigator.connection?.saveData`, `effectiveType` in `slow-2g/2g/3g` | Chromium only (Safari and Firefox lack it: start at T2 there) | **T1** + overview-level COG reads only + no GIBS day/night swap |
| 5 | Low memory | `navigator.deviceMemory <= 2` (coarse, capped, Chromium only) | Chromium | **T1** |
| 6 | Frame-rate probe | 1.5 s `requestAnimationFrame` median > 42 ms after first render | all | drop one tier; never silently upgrade |
| 7 | Few cores | `hardwareConcurrency <= 4` | all (Safari clamps) | T2 max (no T3 looks) |
| 8 | Reduced motion | `matchMedia('(prefers-reduced-motion: reduce)')` | all | keep tier; disable auto-rotate/orbit/springs, `jumpTo` |
| 9 | Reduced transparency / contrast | media queries | modern browsers | solid panels, stronger borders; keep tier |

Rationale: ranks 1-3 are correctness failures (nothing renders), 4-5 protect scarce data and RAM using coarse signals that exist only in Chromium (the dominant Android browser: inference, no share figure fetched), 6-7 are heuristics and the probe is the only signal that exists everywhere, 8-9 are accessibility preferences, not performance. The user always sees "Lite mode" with a one-tap "Switch to full" (Apple: agency); T0 is never an error screen.
```ts
function chooseTier(): 0|1|2|3 {
  const c = document.createElement('canvas'); const gl = c.getContext('webgl2');
  if (!gl) return 0;
  const dbg = gl.getExtension('WEBGL_debug_renderer_info'); const r = dbg ? String(gl.getParameter(dbg.UNMASKED_RENDERER_WEBGL)) : '';
  if (/swiftshader|llvmpipe/i.test(r)) return 0;
  const n: any = navigator, conn = n.connection;
  if (conn?.saveData || /^(slow-2g|2g|3g)$/.test(conn?.effectiveType ?? '')) return 1;
  if (n.deviceMemory && n.deviceMemory <= 2) return 1;
  if (n.hardwareConcurrency && n.hardwareConcurrency <= 4) return 2;
  return matchMedia('(prefers-reduced-motion: reduce)').matches ? 2 : 3;   // probe may still lower this
}
```
